# CombatCore 行为树 (Behavior Tree) 实现指南

## 概述

行为树负责**敌人 AI 的决策层**，放在 `Assets/Scripts/AI/BehaviorTree/` 下。

### BT 和 FSM 的分工

```
行为树 (大脑)                    状态机 (身体)
  │                                │
  ├─ "我应该做什么？"              ├─ "我怎么执行这个动作？"
  ├─ 每帧决策                      ├─ 管理动作的完整生命周期
  ├─ 选择行为                      ├─ 前摇→判定→后摇
  └─ 输出: SetTrigger("Chase")     └─ 接收: 参数变化 → 状态切换
                   ↓
            ─────────────── 共享 ParameterStore ───────────────
```

不要把「决策」和「执行」混在一个 BT 里。经典的错误是让 BT 节点直接控制动画、移动、攻击判定。正确的做法是：**BT 节点只设置 FSM 参数，FSM 负责执行**。

---

## 一、核心概念

### 1.1 三种节点状态

每个节点 Tick 后返回三种结果之一：

```
Success  — 节点完成，父节点继续
Failure  — 节点失败，父节点根据策略处理
Running  — 节点还在执行中，下帧继续 Tick（BT 的核心创新）
```

**Running 的存在是整个 BT 与普通条件判断树的本质区别。** 它允许一个行为跨越多帧，下帧的 Tick 会从之前 Running 的节点继续，而不是从根重新遍历。

### 1.2 节点类型

```
                            BTNode (抽象基类)
                               │
              ┌────────────────┼────────────────┐
              │                │                │
          BTComposite       BTDecorator       BTAction
          (组合节点)        (装饰节点)        (叶子行为)
              │                │
    ┌─────┬───┴───┐    ┌─────┼─────┐
    │     │       │    │     │     │
 Sequence Selector  Parallel Inverter Condition Wait
                             Repeater Cooldown  MoveTo
                             ......
```

### 1.3 每帧 Tick 流程

```
1. BTController.Update()
2.   _root.Tick(blackboard)
3.     如果是 Composite → 按顺序 Tick 子节点
4.       子节点返回 Success → 继续下一个子节点
5.       子节点返回 Running → 立即返回 Running 给父节点
6.       子节点返回 Failure → 取决于父节点类型
7.     直到叶子节点 → 执行具体逻辑 → 返回结果
```

**关键**: 下帧再次 Tick 时，树会从上次返回 Running 的那个节点**恢复执行**。不需要额外保存状态——Running 返回值和树的遍历顺序自然实现了「断点续执」。

## 三、分步要点

### Step 1: `BTNode.cs` — 基类

```csharp
public enum NodeState
{
    Success,
    Failure,
    Running
}

public abstract class BTNode
{
    public NodeState State { get; protected set; }
    
    // 节点首次激活时调用一次
    public virtual void OnEnter(BTBlackboard blackboard) { }
    
    // 节点退出时调用（无论是 Success 还是 Failure）
    public virtual void OnExit(BTBlackboard blackboard) { }
    
    // 核心方法：每帧调用，返回当前状态
    public abstract NodeState Tick(BTBlackboard blackboard);
    
    // 从外部重置节点状态（中断、重新开始等）
    public virtual void Reset()
    {
        State = NodeState.Running;
    }
}
```

**要点**:
- `OnEnter` / `OnExit` 是配对的生命周期回调。在 Tick 内部，第一次调用时自动触发 OnEnter，返回 Success/Failure 时自动触发 OnExit
- `Reset()` 在整棵树重新评估时调用（死亡复活、行为切换等）
- `State` 字段记录上次 Tick 的结果

### 1.1 生命周期自动化

让基类处理 OnEnter/OnExit 的调用时机：

```csharp
public NodeState Tick(BTBlackboard bb)
{
    if (State != NodeState.Running)
        OnEnter(bb);  // 首次进入
    
    State = OnTick(bb);  // 子类实现真正逻辑
    
    if (State != NodeState.Running)
        OnExit(bb);  // 完成时退出
    
    return State;
}

protected abstract NodeState OnTick(BTBlackboard bb);
```

### Step 2: `BTBlackboard.cs` — 黑板

黑板是树的**共享内存**。所有节点通过黑板交换数据，不直接互相引用。

```csharp
public class BTBlackboard
{
    Dictionary<string, object> _data = new();
    
    public void Set<T>(string key, T value) => _data[key] = value;
    public T Get<T>(string key) => _data.TryGetValue(key, out var v) ? (T)v : default;
    public bool TryGet<T>(string key, out T value) { ... }
    public bool Has(string key) => _data.ContainsKey(key);
    public void Remove(string key) => _data.Remove(key);
    public void Clear() => _data.Clear();
}
```

**约定的 Key 命名**:
- `"Target"` — 当前目标 (Transform / GameObject)
- `"TargetDistance"` — 到目标的距离 (float)
- `"IsTargetVisible"` — 目标是否在视野内 (bool)
- `"AgentHealth"` — 自身血量 (float)
- `"LastKnownPosition"` — 目标最后已知位置 (Vector3)
- `"FSMController"` — 指向自身的 FsmController 引用（用于设置参数）

**为什么用黑板而不是节点互相引用?**

BT 节点如果互相引用，就变成了有向图——难以序列化和可视化编辑。黑板作为一个扁平 KV 存储，节点只和黑板交互，彼此解耦。

### Step 3: `BTComposite.cs` — 组合节点

#### Sequence（顺序节点）

从左到右依次执行子节点。任一失败 → 整体失败。全部成功 → 整体成功。

```
     [Sequence]
    /    |    \
  [A]  [B]    [C]
  
Tick 1: A → Running，Sequence 返回 Running
Tick 2: A → Success，继续 B
Tick 2: B → Running，Sequence 返回 Running
Tick 3: B → Success，继续 C
Tick 3: C → Success，Sequence 返回 Success
```

```csharp
public class Sequence : BTNode
{
    List<BTNode> _children;
    int _currentIndex;

    public override void OnEnter(BTBlackboard bb)
    {
        _currentIndex = 0;
    }

    protected override NodeState OnTick(BTBlackboard bb)
    {
        while (_currentIndex < _children.Count)
        {
            var child = _children[_currentIndex];
            var state = child.Tick(bb);
            
            if (state == NodeState.Failure)
                return NodeState.Failure;
            
            if (state == NodeState.Running)
                return NodeState.Running;
            
            // state == Success → 继续下一个
            _currentIndex++;
        }
        return NodeState.Success;
    }
}
```

**要点**: `_currentIndex` 是 Sequence 的核心。Running 返回时它停在当前子节点，下帧从这个索引继续。这是 BT 的「断点续执」机制。

#### Selector（选择节点 / Priority）

从左到右依次尝试子节点。任一成功 → 整体成功。全部失败 → 整体失败。

```
     [Selector]
    /    |    \
逃跑   攻击   巡逻
```

优先级从左到右递减：先尝试逃跑（血量低？），不满足再尝试攻击（有目标？），都不满足最后巡逻。

```csharp
public class Selector : BTNode
{
    List<BTNode> _children;
    int _currentIndex;

    protected override NodeState OnTick(BTBlackboard bb)
    {
        while (_currentIndex < _children.Count)
        {
            var child = _children[_currentIndex];
            var state = child.Tick(bb);
            
            if (state == NodeState.Success)
                return NodeState.Success;  // 找到可用行为
            
            if (state == NodeState.Running)
                return NodeState.Running;  // 执行中
            
            // state == Failure → 尝试下一个
            _currentIndex++;
        }
        return NodeState.Failure;
    }
}
```

**一个常见的「行为中断」问题**:

当 Selector 的第 2 个子节点 (攻击) 正在 Running，第 1 个子节点 (逃跑) 的条件变得满足了（血量突然低于阈值），要不要中断攻击？

**传统 BT 不自动中断。** Selector 已经停在了索引 1（攻击），不会回头检查索引 0（逃跑）。

要解决这个问题，有两种方案：
1. **条件装饰器挂在 Sequence 里**: 在攻击行为的 Sequence 开头加一个条件装饰器，每帧检查是否该停止攻击
2. **重新评估**: 每帧从根重新开始 Tick，但这放弃了 Running 的断点续执优势

推荐方案 1，更精确：

```
[Selector]
  ├── [Sequence]
  │     ├── [Condition: IsHealthLow]     ← 每帧检查
  │     └── [Action: Flee]
  ├── [Sequence]
  │     ├── [Condition: HasTarget]
  │     ├── [Action: ChaseTarget]
  │     └── [Action: AttackTarget]
  └── [Action: Patrol]
```

### Step 4: `BTDecorator.cs` — 装饰节点

装饰节点只有一个子节点，在子节点执行前后加上额外逻辑。

#### Inverter — 结果取反

```
Success → Failure
Failure → Success
Running → Running (不变)
```

```csharp
public class Inverter : BTNode
{
    BTNode _child;

    protected override NodeState OnTick(BTBlackboard bb)
    {
        var state = _child.Tick(bb);
        return state switch
        {
            NodeState.Success => NodeState.Failure,
            NodeState.Failure => NodeState.Success,
            _ => NodeState.Running
        };
    }
}
```

#### Repeater — 重复执行

```csharp
public class Repeater : BTNode
{
    BTNode _child;
    int _repeatCount;     // -1 = 无限重复
    int _currentCount;

    protected override NodeState OnTick(BTBlackboard bb)
    {
        while (true)
        {
            var state = _child.Tick(bb);
            
            if (state == NodeState.Running)
                return NodeState.Running;
            
            _currentCount++;
            
            if (_repeatCount > 0 && _currentCount >= _repeatCount)
                return NodeState.Success;
            
            if (state == NodeState.Failure)
                return NodeState.Failure;
            
            // Success → 重置子节点，再跑一次
            _child.Reset();
        }
    }
}
```

#### Condition Decorator — 条件守卫

```csharp
public class ConditionDecorator : BTNode
{
    BTNode _child;
    Func<BTBlackboard, bool> _condition;

    protected override NodeState OnTick(BTBlackboard bb)
    {
        if (!_condition(bb))
            return NodeState.Failure;
        return _child.Tick(bb);
    }
}
```

**这是最常用的装饰节点。** 它作为 Sequence 的第一个子节点，如果条件不满足就直接失败 → Sequence 短路 → 父 Selector 尝试下一个行为。

#### Cooldown — 冷却

```csharp
public class Cooldown : BTNode
{
    BTNode _child;
    float _cooldownTime;
    float _lastExecuteTime = float.MinValue;

    protected override NodeState OnTick(BTBlackboard bb)
    {
        if (Time.time - _lastExecuteTime < _cooldownTime)
            return NodeState.Failure;
        
        var state = _child.Tick(bb);
        if (state != NodeState.Running)
            _lastExecuteTime = Time.time;
        return state;
    }
}
```

### Step 5: `BTAction.cs` — 叶子行为节点

叶子节点是真正「做事情」的地方。在这套架构中，叶子行为节点**不直接操作角色**，而是设置 FSM 参数或操作黑板。

#### Wait — 等待

```csharp
public class Wait : BTNode
{
    float _duration;
    float _elapsed;

    protected override NodeState OnTick(BTBlackboard bb)
    {
        _elapsed += Time.deltaTime;
        return _elapsed >= _duration ? NodeState.Success : NodeState.Running;
    }
}
```

#### SetFSMParameter — 设置 FSM 参数（最关键）

```csharp
public class SetFSMParameter : BTNode
{
    string _paramName;
    ParameterType _type;
    object _value;  // bool / int / float / trigger
    
    protected override NodeState OnTick(BTBlackboard bb)
    {
        var fsm = bb.Get<StateMachineController>("FSMController");
        switch (_type)
        {
            case ParameterType.Bool:   fsm.SetBool(_paramName, (bool)_value); break;
            case ParameterType.Int:    fsm.SetInt(_paramName, (int)_value); break;
            case ParameterType.Float:  fsm.SetFloat(_paramName, (float)_value); break;
            case ParameterType.Trigger: fsm.SetTrigger(_paramName); break;
        }
        return NodeState.Success;  // 立即成功，不阻塞
    }
}
```

**这是 BT 和 FSM 的桥梁。** AI 决策「应该攻击」→ BT 节点 `SetFSMParameter("Attack", Trigger)` → FSM 条件检测到 Attack Trigger → 切换到 Attack 状态。

#### MoveToPosition — 移向位置

```csharp
public class MoveToPosition : BTNode
{
    float _stopDistance;
    
    protected override NodeState OnTick(BTBlackboard bb)
    {
        var fsm = bb.Get<StateMachineController>("FSMController");
        var target = bb.Get<Vector3>("MoveTarget");
        var current = bb.Get<Transform>("Self");
        
        float dist = Vector3.Distance(current.position, target);
        if (dist <= _stopDistance)
            return NodeState.Success;
        
        // 设置 FSM 参数，让 FSM 的 Move 状态处理实际移动
        fsm.SetFloat("TargetX", target.x);
        fsm.SetFloat("TargetZ", target.z);
        fsm.SetFloat("Speed", 5f);  // 告诉 FSM 你在跑
        return NodeState.Running;
    }
}
```

### Step 6: `BTCondition.cs` — 叶子条件节点

条件节点只做判断，不改变任何状态：

```csharp
public class HasTarget : BTNode
{
    protected override NodeState OnTick(BTBlackboard bb)
        => bb.TryGet<Transform>("Target", out var t) && t != null
            ? NodeState.Success : NodeState.Failure;
}

public class InRange : BTNode
{
    float _range;
    
    protected override NodeState OnTick(BTBlackboard bb)
        => bb.Get<float>("TargetDistance") <= _range
            ? NodeState.Success : NodeState.Failure;
}

public class IsHealthBelow : BTNode
{
    float _threshold;
    
    protected override NodeState OnTick(BTBlackboard bb)
        => bb.Get<float>("AgentHealth") <= _threshold
            ? NodeState.Success : NodeState.Failure;
}

public class HasBufferedInput : BTNode
{
    protected override NodeState OnTick(BTBlackboard bb)
        => /* 检查输入缓冲 */ NodeState.Success;
}
```

### Step 8: `BTController.cs` — 运行时驱动

```csharp
public class BTController : MonoBehaviour
{
    [SerializeField] BehaviorTreeAsset _asset;
    
    BTNode _root;
    BTBlackboard _blackboard;
    StateMachineController _fsm;
    
    public BTBlackboard Blackboard => _blackboard;

    void Awake()
    {
        _blackboard = new BTBlackboard();
        _fsm = GetComponent<StateMachineController>();
        
        // 必须在 BuildTree 之前设置好黑板的基础数据
        _blackboard.Set("FSMController", _fsm);
        _blackboard.Set("Self", transform);
        
        _root = BuildTree();  // 或从 _asset 反序列化
        _root?.OnEnter(_blackboard);
    }

    void Update()
    {
        // 每帧更新感知数据
        UpdatePerception();
        
        // Tick 行为树
        var state = _root.Tick(_blackboard);
        
        // 树执行完毕 → 重置
        if (state != NodeState.Running)
            _root.Reset();
        
        // 更新 FSM 状态机（在 BT 下面那一层）
        // _fsm 已经在自己的 Update 中运行（通过 MonoBehaviour 顺序保证）
    }
    
    void UpdatePerception()
    {
        // 感知系统检测目标
        // 更新 Target, TargetDistance, IsTargetVisible 等
        _blackboard.Set("TargetDistance", DetectDistance());
        _blackboard.Set("IsTargetVisible", DetectVisibility());
    }
    
    BTNode BuildTree()
    {
        // 示例：巡逻 → 发现 → 追击 → 攻击
        return new Selector(
            // 优先级 1: 逃跑
            new Sequence(
                new IsHealthBelow(0.3f),
                new SetFSMParameter("Flee", ParameterType.Trigger),
                new Wait(3f)
            ),
            // 优先级 2: 攻击
            new Sequence(
                new ConditionDecorator(bb => bb.Get<bool>("IsTargetVisible")),
                new Selector(
                    // 近战 → 接近 + 攻击
                    new Sequence(
                        new InRange(2f),
                        new SetFSMParameter("Attack", ParameterType.Trigger),
                        new Wait(1f)
                    ),
                    // 远距离 → 追击
                    new Sequence(
                        new MoveToPosition(2f)
                    )
                )
            ),
            // 优先级 3: 巡逻
            new Sequence(
                new Patrol()
            )
        );
    }
}
```

**要点**：
- `UpdatePerception()` 需要在 `_root.Tick()` 之前调用。感知数据是 BT 做决策的依据
- BT 和 FSM 在同一个 GameObject 上，BT 设置参数 → FSM 响应参数 → Animator 播放动画
- `BTController` 放在 `FSMController` 的 Update 之前执行（靠 Script Execution Order 保证，或在同一个 Update 里先调 BT 再调 FSM）

## 四、BT + FSM 的配合模式

### 模式 1：BT 设置 Trigger → FSM 过渡

```
BT: HasTarget → Success → SetFSMParam("Chase", Trigger) → Success
FSM: Idle 状态 → 检测到 Chase Trigger → 过渡到 Move 状态 → 移动逻辑由 FSM Move 状态处理
```

**适用于**: 一次性决策，如「开始追击」、「释放技能」

### 模式 2：BT 持续设置数值 → FSM 条件过渡

```
BT: UpdatePerception() → SetFloat("TargetDistance", dist) → Success
FSM: Move 状态 → 过渡条件: TargetDistance < 2.0 → 过渡到 Attack 状态
```

**适用于**: 连续变化的条件，如距离、血量

注意: 这个模式下 BT 叶子节点只管更新黑板和设置 FSM 参数，过渡本身由 FSM 自己的条件评估触发。

### 模式 3：BT Condition 守卫 → 防止 FSM 卡死

```
BT:
[Selector]
  ├── [Sequence]
  │     ├── [Condition: IsHealthBelow 0.3]     ← BT 层检查
  │     ├── SetFSMParam("Flee", Trigger)       ← 通知 FSM 逃跑
  │     └── Wait(3f)                            ← 给 FSM 3 秒执行逃跑
  ├── [Sequence]
  │     ├── [Condition: InRange 2f]            
  │     └── SetFSMParam("Attack", Trigger)      
  └── SetFSMParam("Idle", Trigger)             ← 什么都不做
```

**注意**: BT 的 3-5 个叶子行为之间，FSM 可能会切几个状态（Idle→Move→Attack→Idle），这不影响 BT。BT 的 Wait/Success 是在 BT 自己的时间尺度上跑的，和 FSM 状态切换解耦。

## 五、几个容易踩的坑

### 5.1 不要每帧从根重建树

```csharp
// 错误
void Update() { var root = BuildTree(); root.Tick(bb); }

// 正确
void Awake() { _root = BuildTree(); }
void Update() { _root.Tick(bb); }
```

树应该在 Awake 时构建一次，Update 中只 Tick。因为 Running 节点的内部状态（如 `_currentIndex`、`_elapsed`）必须跨帧保留。

### 5.2 Selector 的优先级陷阱

```
[Selector]
  ├── [Sequence]
  │     ├── HasTarget
  │     └── Attack        ← 如果 Attack 一直在 Running，永远不会回到 HasTarget 检查
  └── Patrol
```

攻击行为开始后，即使目标消失（HasTarget 变 false），BT 也不会自动退出攻击。因为 Selector 已经停在索引 0 的子节点内部。

**修复**: 在 Attack 的 Sequence 里**前面**加一个 `HasTarget` 条件:

```
[Selector]
  ├── [Sequence]
  │     ├── HasTarget      ← 每帧都检查！
  │     ├── MoveToTarget
  │     └── Attack
  └── Patrol
```

这样 Attack Sequence 的每一帧都会先检查 HasTarget。目标一旦丢失，HasTarget 返回 Failure → Sequence 返回 Failure → Selector 尝试 Patrol。

### 5.3 黑板 Key 命名用常量

```csharp
public static class BBKeys
{
    public const string Target = "Target";
    public const string TargetDistance = "TargetDistance";
    public const string AgentHealth = "AgentHealth";
    // ...
}
```

字符串拼写错误是编译期发现不了的 bug。集中定义 Key 常量。

### 5.4 不要和 Animator 的 Update 抢顺序

建议 Script Execution Order:
```
BTController.Update()    ← 先跑 (决策)
FsmController.Update()   ← 后跑 (执行)
```

或者合并到一个 Manager 里用同一个 Update:

```csharp
void Update()
{
    UpdatePerception();
    _btRoot.Tick(_blackboard);
    _fsm.Update(Time.deltaTime, animNormalizedTime);
}
```

## 六、和后续感知系统的对接

你的规划里 AI 模块还有 `Perception/`（感知系统），负责视野、听觉检测。它输出的数据直接写到 `BTBlackboard` 里:

```
PerceptionSystem.Update():
  ├── 射线检测: 目标是否在视野内？
  ├── 距离计算: 到目标的距离
  └── 写入黑板:
       _blackboard.Set("Target", detectedTarget);
       _blackboard.Set("TargetDistance", distance);
       _blackboard.Set("IsTargetVisible", isVisible);
       _blackboard.Set("LastKnownPosition", lastPos);
```

BT 的条件节点读取这些 Key 做判断，感知系统只负责写入数据，不直接做决策。

## 七、一个完整的敌人 AI 树示例

```
[Selector]  ← 优先级从高到低
│
├── [Sequence]  ← 死亡处理
│     ├── [Condition: IsDead]
│     └── [Wait: forever]  ← 死了就永远不动
│
├── [Sequence]  ← 受击反应
│     ├── [Condition: IsStunned]
│     └── [Wait: 0.5s]  ← 硬直动画时长
│
├── [Sequence]  ← 逃跑 (HP < 30%)
│     ├── [Condition: HealthBelow 0.3]
│     ├── [SetFSMParam: "Flee", Trigger]
│     └── [MoveTo: fleeTarget, 10m]
│
├── [Sequence]  ← 攻击
│     ├── [Condition: HasTarget]
│     ├── [Condition: InRange 2f]
│     ├── [SetFSMParam: "Attack", Trigger]
│     └── [Wait: 0.8s]
│
├── [Sequence]  ← 追击
│     ├── [Condition: HasTarget]
│     ├── [SetFSMParam: "Chase", Trigger]
│     └── [MoveTo: target.position, 2f]
│
└── [Sequence]  ← 巡逻 (兜底)
      ├── [SetFSMParam: "Patrol", Trigger]
      ├── [MoveTo: patrolPoint, 0.5f]
      └── [Wait: 2s]  ← 到达后停留 2 秒
```
