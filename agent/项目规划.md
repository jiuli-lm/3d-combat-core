# CombatCore 3D 战斗核心系统 — 项目规划

## 一、项目概述

**项目名称**：CombatCore  
**项目类型**：Unity 3D 战斗核心框架  
**目标平台**：PC 
**美术风格**：二次元 / 科幻 / 都市幻想  

本项目旨在构建一套可复用、可扩展的 3D 动作战斗核心系统，支持角色控制、技能释放、连招、状态机、AI 行为以及关卡战斗等完整战斗闭环。

---

## 二、核心模块规划

### 2.1 3D 动作系统（3D Action）

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 移动与导航 | 基于 NavMesh / CharacterController 的移动系统，支持行走、奔跑、闪避 | P0 |
| 跳跃与下落 | 重力模拟、多段跳、缓落 | P1 |
| 攀爬与翻越 | 环境交互：攀墙、翻越障碍 | P2 |
| 受击与僵直 | 受击反馈、击退、击飞、倒地 | P0 |
| 硬直与霸体 | 硬直帧、霸体状态、超级霸体 | P1 |

### 2.2 角色控制（Character Control）

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 输入抽象层 | 基于 Unity Input System，支持键盘/手柄，输入缓冲 | P0 |
| 角色属性 | HP、MP/能量、攻击力、防御力、速度等数值系统 | P0 |
| 角色状态 | 待机、移动、攻击、受击、死亡等全局状态管理 | P0 |
| 锁定目标 | 软锁定 / 硬锁定切换，目标切换逻辑 | P1 |
| 相机控制 | 第三人称跟随相机、战斗相机运镜 | P1 |

### 2.3 技能系统（Skill System）

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 技能定义 | ScriptableObject 配置：伤害、范围、冷却、消耗、动画 | P0 |
| 技能释放 | 技能前摇 → 判定 → 后摇 → 冷却 完整生命周期 | P0 |
| 技能类型 | 近战、远程、AOE、Buff/Debuff、位移技、召唤技 | P0 |
| 技能取消 | 技能可取消窗口（Cancel Window），连招衔接 | P1 |
| 技能特效 | VFX 特效触发、音效、屏幕震动 | P1 |
| 技能升级 | 技能等级、派生技能树 | P2 |

### 2.4 状态机（State Machine）

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 有限状态机 | 通用 FSM 框架，支持状态进入/退出/更新回调 | P0 |
| 状态过渡 | 条件过渡、AnyState 过渡、过渡优先级 | P0 |
| 动画状态机 | 与 Animator 同步，动画事件回调 | P0 |
| 层级状态机 | 子状态机支持（如：移动态下分行走/奔跑） | P1 |
| 可视化调试 | 运行时状态切换日志 / Gizmos 调试 | P2 |

### 2.5 连招系统（Combo System）

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 连招表 | 连招链配置：前置技能 → 后续技能 → 分支 | P0 |
| 输入窗口 | 连招输入缓冲窗口、预输入判定 | P0 |
| 连招计数 | 连击数统计、连击伤害加成 | P1 |
| 浮空连招 | 浮空判定、空中追击、空中连段 | P1 |
| 终结技 | 连击达到条件触发终结/处决技 | P2 |

### 2.6 敌人 AI（Enemy AI）

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 行为树 / FSM | 基于行为树或状态机的 AI 决策框架 | P0 |
| 感知系统 | 视野、听觉、警戒范围 | P0 |
| 战斗行为 | 巡逻 → 发现 → 追击 → 攻击 → 撤退 行为循环 | P0 |
| 队伍协作 | 多敌人协同攻击、包围策略 | P1 |
| Boss AI | 多阶段 Boss 战、特殊机制 | P1 |
| 难度调节 | 基于玩家表现的动态难度 | P2 |

### 2.7 关卡战斗（Level Combat）

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 战斗区域 | 战斗区域触发、边界限制、空气墙 | P0 |
| 波次管理 | 敌人波次生成、波次配置 | P0 |
| 战斗事件 | 关卡内触发器：陷阱、机关、场景破坏 | P1 |
| 战斗评分 | 通关评分系统（时间、连击、受伤） | P1 |
| 剧情战斗 | 对话/过场穿插的剧情战斗 | P2 |

## 三、技术架构

```
CombatCore/
├── Core/                    # 核心框架
│   ├── StateMachine/        # 通用状态机
│   ├── EventSystem/         # 事件总线
│   ├── ObjectPool/          # 对象池
│   └── Singleton/           # 单例基类
├── Character/               # 角色系统
│   ├── CharacterController/ # 角色移动控制
│   ├── Attribute/           # 属性系统
│   └── Animation/           # 动画管理
├── Combat/                  # 战斗系统
│   ├── Skill/               # 技能系统
│   ├── Combo/               # 连招系统
│   ├── Damage/              # 伤害计算
│   ├── Hitbox/              # 碰撞检测
│   └── Buff/                # Buff/Debuff
├── AI/                      # AI 系统
│   ├── BehaviorTree/        # 行为树
│   ├── Perception/          # 感知
│   └── Decision/            # 决策
├── Level/                   # 关卡战斗
│   ├── Spawner/             # 敌人生成
│   └── Trigger/             # 关卡触发器
├── UI/                      # 战斗 UI
│   ├── HUD/                 # 血量/能量/技能栏
│   └── ComboDisplay/        # 连击显示
└── Data/                    # 数据配置
    ├── Characters/          # 角色数据 SO
    ├── Skills/              # 技能数据 SO
    └── Levels/              # 关卡数据 SO
```

## 五、关键设计决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| 动画系统 | Unity Animator + Animation Rigging | 原生支持好，社区成熟 |
| AI 框架 | 自研轻量行为树 | 避免过度依赖第三方，可控性强 |
| 输入系统 | Unity New Input System | 跨平台输入映射 |
| 数据配置 | ScriptableObject | 可视化编辑，易于策划使用 |
| 碰撞检测 | 自研 Hitbox 系统 | 比 Unity 物理更精确可控 |
| 渲染管线 | URP | 跨平台性能好，适合风格化渲染 |

## 六、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 连招手感受差 | 高 | 充分预输入缓冲，动画取消窗口调优 |
| AI 行为单一 | 中 | 行为树 + 配置驱动，策划可调 |
| 性能瓶颈 | 中 | 前期建立对象池，LOD 管理，Profile 定期检查 |
| 多人协作冲突 | 低 | 模块解耦，接口先行，Git 分支策略 |
